The overall picture

      

        
#Join typeWhat it keepsIn this database

          
1INNER JOINOnly matching rowsDrops Taco House, Priya, and AAAA

          
2LEFT JOINAll rows from the left table + matchesKeeps Taco House (from Restaurant50)

          
3RIGHT JOINAll rows from the right table + matchesKeeps Priya and AAAA (to Customer50)

          
4FULL OUTER JOINAll rows from both tables (LEFT + RIGHT + UNION in MySQL)Keeps everyone: 11 rows

          
5SELF JOINA table joined with itselfCustomers in the same city, repeat reviews

          
6NATURAL JOINAutomatic match on all same-named columnsAccidentally matches on City

        

      

      

        
Aggregation reminders

        
    
          
  • JOIN first, then WHERE, then GROUP BY, then HAVING. The step chips in Watch it run show this order.
    • 
          
  • With LEFT or RIGHT JOIN, count a column from the optional side — COUNT(rev.ReviewID), not COUNT(*).
    • 
          
  • Use COUNT(DISTINCT …) when the same person or item can appear more than once.
    • 
          
  • AVG of no rows is NULL, not 0.
